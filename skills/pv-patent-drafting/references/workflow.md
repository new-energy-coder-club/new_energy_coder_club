# 六阶段方法论（详细版）

## 阶段 1：查新检索（PRIOR_ART_REPORT.md）

1. **特征提取**：用代码探索代理拆解目标系统的算法实现，产出 4–8 条候选技术特征（每条：一句话 + 代码位置）。
2. **检索**：
   - 中文：专利汇/万方转载页（xjishu）、CNIPA；英文：Google Patents（`site:patents.google.com`）
   - 学术：Google Scholar、会议论文（如 Solar Energy、SimBuild）
   - **非专利现有技术同样重要**：商用软件用户手册、招股书、竞品产品文档、新闻报道
3. **对照矩阵**：特征 × 最接近文献，判断单篇是否全覆盖 → 输出每条特征的新颖性强弱。
4. **结论**：PATENTABLE / WITH AMENDMENTS / NOT PATENTABLE + 独权锚定建议 + 勿踩雷区（已被击穿的特征）。
5. 未核实的专利号一律标 `[VERIFY]`，禁止编造。

## 阶段 2：技术交底书（INVENTION_DISCLOSURE.md）

- 问题必须来自现有技术缺陷（技术性，非商业性）；方案描述机制而非结果。
- 三层分解：**核心发明构思**（去掉就不新颖的最小特征集 → 独权）、**支撑特征**（从权素材）、**可选特征**（实施例素材）。
- 附图计划表（图号/类型/内容/支撑特征）+ 权利要求依赖映射树。
- 与最接近现有技术的对比表（按维度逐列区分）。

## 阶段 3：权利要求书（CLAIMS.md）

- CN 两部式："一种……，其特征在于，包括："；独立/从属**混编连续编号**。
- 主题组合：方法独权 + 系统独权（镜像模块）+ 存储介质独权；总条数 ≤ 20。
- 独权 = 最小可辩护特征集，不写非必要限定；每条从权是独立退守位，各加一个有意义的限定。
- 无结果性限定（"以实现高精度"）、无相对术语、先行词一致（首次"一"，其后"所述"）。
- 附"权项总览表"：每条权项的关键限定 + 规避的现有技术 + 撰写说明（供代理人）。

## 阶段 4：附图

- SVG 手写（黑白线条、白底、SimSun、附图标记 110/120…）；图内嵌图号标题。
- 必备：系统结构框图、方法流程图、核心机理示意图、实施效果对比图。
- 附图标记对照表（标记 → 含义）放入 `figures/README.md`。
- Edge 无头截图渲染 → 逐张目检 → 修复重叠/裁切 → PIL 裁白边。

## 阶段 5：说明书（specification/）

分节文件：`title / technical_field / background / summary / drawings_description / detailed_description / abstract + SPECIFICATION_INDEX.md`。

- 背景：2–3 类最接近方案 + 各自**技术性**缺陷；不引用具体专利号；不夸现有技术。
- 发明内容：问题/方案/效果三段式；**无公式、无实验数值**，效果为结构化定性论述。
- 具体实施方式：≥1 个完整实施例 + 变型例 + 存储介质实施例；参数给优选范围（支持独权解释）；附图标记与附图一致。
- 摘要 ≤ 300 字。
- 强制输出"权利要求支撑核查表"，每条权项每个特征都要有说明书出处。

## 阶段 6：交付物生成

### 6a 企业交底书 docx 模板（scripts/fill_disclosure.py）

1. 用 WIR 引擎 `session.read(part='document')` 读出模板 WIR，确定每个待替换段落的 P 键与 run class；
2. 构造 EDITS 列表（P 键 → 新文本），脚本自动保留段落格式替换；
3. 图片：先 `crop_figs.py` 裁白边，按版心宽度换算点数（1pt = 12700 EMU）嵌入；图多时追加 image+caption 段落；
4. 后处理：`wp:inline` → `wp:anchor + wrapTopAndBottom`（上下型环绕，水平居中）；
5. 保存到新文件（勿覆盖打开中的文件）；mammoth 转 HTML 截图复核。

### 6b 立项 PPT（scripts/add_patent_slide.py）

- 在平台介绍页后插入"知识产权布局"页：专利名称、核心创新点、查新结论、业务价值、申报计划 + 右侧效果对比图；
- 通过 `prs.slides._sldIdLst` 重排把新页移到目标位置；
- 文字风格（字体/字号/标签样式）模仿同 deck 已有页面。

## 效果论述素材化

写"与现有技术相比的有益效果"时，优先引用真实业务痛点（内部工具调研、群聊讨论、竞品试用结论），按"对比对象 → 痛点依据 → 本发明效果"三段式组织；竞品名称在正式申请文件中泛化（"某建模类工具"），内部版本可点名。
